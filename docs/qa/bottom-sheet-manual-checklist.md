# 바텀시트 수동 전수점검 체크리스트

## 목적과 범위

- 점검 기준일: 2026-08-14
- 대상 라이브러리: `@gorhom/bottom-sheet` 5.2.14
- 대상 플랫폼: iOS 실기기, Android 실기기
- 대상 빌드: Debug와 Release를 각각 확인한다.
- 조사 방법: 라이브러리 import, 공통 래퍼, 사용자 화면 호출부, 앱 루트 Provider를 함께 검색했다.

이 문서는 `@gorhom/bottom-sheet`를 직접 또는 공통 래퍼를 통해 사용하는 사용자 화면 9개를 다룬다. 일반 React Native `Modal`, `react-native-modal`, 드롭다운, 팝업 메뉴는 같은 이름이나 모양을 가질 수 있어도 이 라이브러리의 바텀시트가 아니므로 아래 전수점검 대상에서 제외한다.

## 테스트 데이터 준비

택시 채팅 바텀시트 5개를 모두 열려면 한 가지 파티 상태만으로는 부족하다.

- 모집 중 또는 모집 마감 상태의 파티 리더 계정
- 도착 완료 상태이며 정산 대상 멤버가 여러 명인 파티 리더 계정
- 계좌 정보가 저장된 계정과 저장되지 않은 계정
- 시간표에 등록된 강의가 1개 이상인 학기
- 한 화면을 넘길 만큼 검색 결과가 많은 강의 검색어

## 공통 동작 체크리스트

| 항목 | iOS | Android | 확인 기준 |
| --- | --- | --- | --- |

| 닫은 뒤 다시 열기 | [ ] | [ ] | 닫기 버튼, 배경 터치, 아래로 끌기 후 각각 다시 열린다. |
| 배경과 중첩 | [ ] | [ ] | 배경이 어두워지고 기존 화면보다 위에 표시된다. 다른 팝업과 겹치지 않는다. |
| 드래그 닫기 | [ ] | [ ] | 핸들 또는 콘텐츠를 아래로 끌면 자연스럽게 닫힌다. |
| 콘텐츠 스크롤 | [ ] | [ ] | 긴 콘텐츠가 실제로 이동하며 처음과 끝까지 도달한다. 단순 탄성 효과만 보이면 실패다. |
| 스크롤과 시트 제스처 | [ ] | [ ] | 목록을 스크롤할 때 시트가 먼저 닫히지 않고, 목록 맨 위에서 아래로 끌 때만 시트 닫기가 이어진다. |
| 좌우 여백 | [ ] | [ ] | 제목, 닫기 버튼, 카드와 행이 둥근 시트 가장자리에 붙거나 잘리지 않는다. |
| 상하 안전 영역 | [ ] | [ ] | 노치와 홈 인디케이터, Android 시스템 내비게이션 영역에 콘텐츠가 가려지지 않는다. |
| 작은 화면 | [ ] | [ ] | 글자 확대 또는 작은 기기에서도 마지막 버튼까지 접근할 수 있다. |
| 키보드 | [ ] | [ ] | 입력창 포커스 시 해당 입력창과 하단 버튼이 키보드에 가려지지 않고, 키보드를 닫아도 위치가 정상 복원된다. |
| 로딩과 연속 탭 | [ ] | [ ] | 데이터 로딩 중 및 완료 직후 열어도 중복 표시, 무반응, 종료가 없다. |
| 접근성 | [ ] | [ ] | 스크린 리더가 제목, 닫기, 토글, 선택 상태를 이해 가능한 순서로 읽는다. |

## 사용자 화면 9개

### 1. 공지 알림 설정

- 진입: 공지 화면 상단의 `공지 알림 설정 열기` 버튼
- 구현: `NoticeSettingsPanel`
- 구조: `BottomSheetModal` 안의 `BottomSheetScrollView`

추가 점검:

- [ ] iOS: 전체 알림과 모든 세부 카테고리를 끝까지 스크롤할 수 있다.
- [ ] Android: 전체 알림과 모든 세부 카테고리를 끝까지 스크롤할 수 있다.
- [ ] 전체 알림을 끄면 세부 토글의 비활성 상태가 즉시 반영된다.
- [ ] 저장 중 연속 탭에도 토글 상태가 꼬이지 않는다.
- [ ] 닫았다 다시 열었을 때 서버에 저장된 값이 표시된다.

### 2. 시간표 학기 선택

- 진입: 시간표 상세 화면 상단의 학기 이름
- 구현: `TimetableSemesterSheet` → `TimetableBottomSheet`
- 구조: 고정 헤더와 `BottomSheetScrollView`

추가 점검:

- [ ] iOS: 학기 항목이 많을 때 마지막 항목까지 스크롤할 수 있다.
- [ ] Android: 학기 항목이 많을 때 마지막 항목까지 스크롤할 수 있다.
- [ ] 현재 학기의 선택 표시와 체크 아이콘이 정확하다.
- [ ] 다른 학기를 누르면 시트가 닫히고 시간표가 선택한 학기로 갱신된다.

### 3. 시간표 강의 추가

- 진입: 시간표 상세 화면 우측 상단의 `+` 버튼
- 구현: `TimetableAddCourseSheet` → `TimetableBottomSheet`
- 높이: 화면의 88%

강의 검색 탭:

- [ ] iOS: 검색 결과 목록을 위아래로 움직여 처음과 끝까지 도달한다.
- [ ] Android: 검색 결과 목록을 위아래로 움직여 처음과 끝까지 도달한다.
- [ ] 스크롤 중 추가 결과 로딩이 중복 호출되지 않고 기존 위치가 갑자기 이동하지 않는다.
- [ ] 검색창에 입력해도 키보드가 결과 목록과 항목 추가 버튼을 가리지 않는다.
- [ ] 결과 없음, 최초 로딩, 추가 로딩, 오류와 다시 시도 상태가 각각 정상이다.
- [ ] 색상 선택 후 강의를 추가하면 시간표 블록의 색상이 일치한다.

직접 입력 탭:

- [ ] iOS: 첫 입력란부터 `강의 추가하기` 버튼까지 스크롤할 수 있다.
- [ ] Android: 첫 입력란부터 `강의 추가하기` 버튼까지 스크롤할 수 있다.
- [ ] 온라인 수업을 켜고 끌 때 강의실·요일·교시 입력 영역이 올바르게 바뀐다.
- [ ] 강의명, 교수명, 강의실 입력 중 현재 입력란이 키보드 위로 올라온다.
- [ ] 학점, 요일, 시작·종료 교시의 선택 상태와 유효성 검사가 정확하다.
- [ ] 유효한 값일 때만 `강의 추가하기` 버튼이 활성화된다.

### 4. 시간표 강의 상세

- 진입: 시간표의 특정 강의 블록
- 구현: `TimetableCourseDetailSheet` → `TimetableBottomSheet`
- 높이: 화면의 63%

추가 점검:

- [ ] iOS: 제목 앞 색상 점과 닫기 버튼이 좌우 시트 가장자리에서 각각 20px 떨어져 보인다.
- [ ] Android: 제목 앞 색상 점과 닫기 버튼이 좌우 시트 가장자리에서 각각 20px 떨어져 보인다.
- [ ] 교수, 강의실, 수업 시간, 학점 행의 구분선과 아이콘이 잘리거나 넘치지 않는다.
- [ ] 긴 강의명은 한 줄에서 말줄임되고 닫기 버튼을 밀어내지 않는다.
- [ ] `강의 삭제`를 누르면 해당 강의만 제거되고 시트가 정상 종료된다.

### 5. 택시 호출

- 진입: 종료 전 택시 파티 채팅 → 입력창 좌측 `+` → `택시 호출`
- 구현: `TaxiTaxiCallSheet` → `TaxiChatBottomSheet`
- 이용 가능 역할: 리더와 일반 멤버

추가 점검:

- [ ] 카카오T, Uber, 티머니GO 항목과 아이콘이 모두 보인다.
- [ ] 각 항목을 누르면 대응 앱 또는 안내 흐름으로 연결되고 시트가 남아 입력을 가리지 않는다.
- [ ] 외부 앱이 설치되지 않은 경우 오류 안내가 이해 가능하다.

### 6. 계좌 전송

- 진입: 종료 전 택시 파티 채팅 → 입력창 좌측 `+` → `계좌 전송`
- 구현: `TaxiAccountSheet` → `TaxiChatBottomSheet`
- 이용 가능 역할: 리더와 일반 멤버

추가 점검:

- [ ] 이름, 은행명, 계좌번호 입력란이 키보드에 가려지지 않는다.
- [ ] 은행 드롭다운이 시트나 키보드 뒤에 가려지지 않고 모든 은행을 선택할 수 있다.
- [ ] `이름 가리기`, `계좌 정보 저장하기` 상태가 전송 데이터와 일치한다.
- [ ] 필수값을 모두 입력한 경우에만 `전송` 버튼이 활성화된다.
- [ ] 저장된 계좌가 있을 때 초기값이 표시되고, 닫았다 다시 열어도 이전 임시 입력이 섞이지 않는다.

### 7. 파티 수정

- 진입: 모집 중 또는 모집 마감 상태의 파티 리더 → 채팅 상단 메뉴 → `수정하기`
- 구현: `TaxiPartyEditSheet` → `TaxiChatBottomSheet`

추가 점검:

- [ ] 시간 선택 휠을 조작할 때 시트 자체가 함께 끌려가지 않는다.
- [ ] 오늘과 내일로 넘어가는 시간 요약이 정확하다.
- [ ] 상세 설명을 입력할 때 입력란과 하단 버튼이 키보드에 가려지지 않는다.
- [ ] 취소 후 재진입하면 서버의 현재 값이 다시 표시된다.
- [ ] 수정 완료 후 채팅 요약 카드에 새 시간과 설명이 반영된다.

### 8. 택시 도착 및 정산

- 진입: 모집 중 또는 모집 마감 상태의 파티 리더 → 입력창 좌측 `+` → `택시 도착`
- 구현: `TaxiArriveSettlementSheet` → `TaxiChatBottomSheet`

추가 점검:

- [ ] 이름, 은행, 계좌번호, 총 택시비 입력 중 각 입력란이 키보드 위에 유지된다.
- [ ] 은행 드롭다운이 다른 멤버 행이나 시트 뒤로 가려지지 않는다.
- [ ] 리더는 자동 포함되고 다른 멤버는 개별 선택·해제할 수 있다.
- [ ] 멤버가 많은 경우 마지막 멤버와 제출 버튼까지 스크롤할 수 있다.
- [ ] 유효한 계좌, 택시비, 정산 대상이 있을 때만 제출할 수 있다.
- [ ] 제출 후 파티 상태와 정산 안내가 한 번만 갱신된다.

### 9. 정산 현황 관리

- 진입: 도착 완료 상태의 파티 리더 → 입력창 좌측 `+` → `정산 현황`
- 구현: `TaxiSettlementStatusSheet` → `TaxiChatBottomSheet`

추가 점검:

- [ ] 총 택시비, 정산 인원, 1인당 금액, 계좌 정보가 실제 정산 데이터와 일치한다.
- [ ] 멤버가 많은 경우 마지막 멤버와 `닫기` 버튼까지 스크롤할 수 있다.
- [ ] 대기, 완료, 파티 나감 상태의 색상과 문구가 구분된다.
- [ ] 리더의 `정산완료` 버튼을 연속 탭해도 요청이 중복되지 않는다.
- [ ] 처리 후 해당 멤버만 완료 상태로 바뀌고 전체 완료 요약도 갱신된다.

## 이번 점검에서 제외한 유사 UI

다음 UI는 바텀시트가 아니라 일반 모달, 드롭다운 또는 팝업이다. 바텀시트 라이브러리 호환성 점검에는 포함하지 않되, 별도의 앱 전체 모달 QA를 할 때 확인한다.

- 관리자 로그인 모달
- 신고 사유 모달
- 강제 업데이트 모달
- 이미지 확대 모달
- 마인크래프트 서버 안내 모달
- 택시 동승 요청 모달
- 은행과 기타 선택 드롭다운
- 채팅 및 화면 상단 팝업 메뉴

자동 테스트, 린트, 타입 검사와 네이티브 빌드 성공만으로 실제 손가락 스크롤, 드래그 충돌, 키보드 가림, 좌우 패딩을 증명할 수 없다. 이 문서의 실기기 체크 결과를 최종 QA 근거로 사용한다.
